# Source Quality

Use source authority appropriate to the claim.

1. Native live data tool when it is the designated source of truth for the domain
2. Official documentation or status page
3. Official package registry, API, release notes, or repository
4. Primary institutional source
5. Reputable secondary reporting

For technical implementation, a current official doc page beats a remembered example. A registry beats a blog for the currently published package version. A versioned release note beats the latest landing page when the user pinned an older version.

When a source is stale, mirrored, or undated, reduce confidence and look for a better one.
